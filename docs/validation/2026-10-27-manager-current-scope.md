# Pi Manager：当前交付范围

日期：2026-10-27；工作分支：`codex/manager-service`。本文是当前状态摘要，不替代逐项验收记录。

## 两个产品

- Pi Web `v1`：Pi 内加载的聊天扩展；独立验收记录在 Web 仓库。此次继续开发没有修改它，也没有给正在使用的扩展安装更新。
- Pi Manager：本仓库中的独立管理产品，合并原 Hub 门户与 Gate 的管理职责；不能等 Pi 启动后再由 Pi 加载管理器。

一个主管入口在可信本机开发时启动公共入口、独立管理员入口、任务执行器、会话门户四个服务。四个服务不是四套产品，也不意味着端口分离就实现了权限隔离。

## 新接入的只读版本目录

`c82602f` 增加了公共／管理员 `POST /api/manager/versions`、`ExecutorClient.versions()`、MCP `manager_list_pi_versions` 和管理页的搜索／分页。只查询固定的官方 Pi 包；不能通过请求指定 registry、包名、传输或超时。目录展示不代表某版本兼容，也不会创建、批准或执行更新任务。

目录查询不占任务变更队列；同一目录刷新合并，请求数量有上限。Manager 的官方元数据请求最多等 2500 毫秒，保留现有 RPC／HTTP 的超时限制。页面区分最新目录、过期缓存和不可用；后发搜索或退出登录后，不接受旧查询回填页面。

定向审查发现管理员退出请求尚未返回时，旧目录查询仍可能回填。`154d8ea` 在退出处理的第一个 await 前使查询代次失效；实际分发脚本的受控管理员回归先观察到 RED（5 通过／1 失败），修改后 6/6 通过。这不是浏览器端到端验收。

后续定向复审发现，退出失败会让已取消查询的状态停在“查询中”。`4adfd52` 增加退出期间的暂停状态和失败后的明确重试状态，不把失败说成退出成功，仍允许已登录管理员主动重新查询。新增负面回归先观察 RED（6 通过／1 失败），修改后 7/7 通过；真实浏览器仍未运行。
