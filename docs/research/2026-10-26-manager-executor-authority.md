# 网页、执行器与 Agent：实际权限域检查

日期：2026-10-26。依据：已批准拆分设计第 2、6、7 节及下一阶段计划的全局约束。
状态：实施前的权限边界核对，**不是已通过隔离验收**。

## 已确定与未确定的事

已确定：公共网页/MCP 入口不应直接导入原生启动器或持有 Docker 控制接口；执行器按冻结任务引用核对精确请求、审批和策略；Agent 不能从提交/查询凭据获得审批权限。

未确定：本机原生 Agent 和执行器使用哪个实际账户/容器权限域。仅启动两个 Node 进程、改变 HOME 或设置文件 0600，不能防止同一 UID 的不受限原生 Agent 读取和修改管理员文件。这不是加一个应用层 scope 或模拟一次 403 就能证明安全的边界。

本轮 Task 1 的私有存储和 Task 2 的原生后端只用于受信本机库调用与隔离测试，不提供 HTTP/MCP 执行入口。工作区启动路径的白名单不等于限制 Pi 工具只能访问那个工作区。

## 进入 Task 3 前必须落实

| 权限域 | 应有能力 | 不应取得的能力 |
| --- | --- | --- |
| 网页/MCP 入口 | 按认证身份提交受限描述、查询任务、转交精确冻结引用 | 任意 shell、宿主 PID 接管、Docker socket、改写执行策略 |
| 执行器 | 独占权威任务状态，验证独立审批及请求版本，执行允许的生命周期动作 | 信任前端任意指定的 executable/argv/PID，跳过审批核对 |
| Pi / Agent | 使用自己的会话凭据、允许的项目、必需的模型访问能力 | 管理员审批凭据、执行器策略、可写管理代码、无限制宿主控制接口 |

任务存储的单写入约束不能在接线时变成“网页与执行器各开一个写入者”。接线必须明确权威存储所在的权限域，以及低权限入口如何提交请求/查询状态。审批需绑定精确任务和修订号/内容，不能仅把状态改成 queued 当作审批证明。

## 可选落地方式与验收要求

1. **账户分离**：管理员预先提供独立账户及最小权限的执行入口，管理状态不向 Agent 账户开放。需要真实验证读取、改写、直接调用执行器和自我批准均失败；不能由开发任务静默创建系统账户或配置无限 sudo。
2. **容器分离**：低权限网页、受限执行器与 Agent 的挂载/控制权限分开，Agent 不接触管理状态与 Docker socket。必须检查实际挂载、网络、凭据和 UID/文件访问边界；容器名、同名卷或应用层 token 本身不是验收证据。
3. **受信本机开发模式**：只能在明确接受同 UID 信任假设时使用，清楚标明不防本机 Agent 读取管理员文件。不作为不可信 Agent 的管理模式，不悄悄开放等价的 MCP 写入/审批能力。

当前没有选用并部署上述任何新权限配置。临时 Pi 的进程通信、生成和退出测试，也不能计为这些权限隔离已通过。

## 不在本轮默许执行的操作

- 不创建宿主账户，不变更组或 sudo 配置。
- 不向 Agent 挂载 Docker socket、整个宿主 HOME 或管理状态根。
- 不启动/替换生产 Hub、Gate、Pi，不迁入真实会话或审批数据库。
- 不把只返回 unavailable 的占位 HTTP/MCP 处理器算作统一服务已实现。

继续开放管理网页的创建/停止动作前，应明确实际权限落地方式和临时隔离验收范围。若需要容器验收，先取得对新建测试容器/测试卷的授权，使用明确可识别的自有临时资源，不复用生产卷；源码开发的授权不等同于生产迁移授权。
