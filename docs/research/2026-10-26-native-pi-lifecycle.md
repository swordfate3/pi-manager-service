# 原生 Pi 管理：本机协议依据

日期：2026-10-26。状态：研究依据，尚无新的原生后端实现。

已读取本机开发依赖中的 Pi 官方 `docs/rpc.md`；来源为 Web 开发目录 `node_modules/@earendil-works/pi-coding-agent/docs/rpc.md`，当次读取的包版本为 `1.1.0`。该路径仅用于本轮核对，不是管理器运行依赖。

后续实施需要遵守的协议事实与测试边界：

- RPC 是常驻子进程，用 stdin/stdout 的 JSONL 通信。持续读取 stdout，否则反压可以阻塞 Pi；诊断与协议输出分开。
- JSONL 按 LF 分割，不能用会把 Unicode 行分隔符也当作记录边界的读取方式。
- 命令响应通过 ID 关联；prompt 成功响应只代表请求被处理，不代表模型已经结束。
- Pi 的文档明确区分 `agent_end` 和 `agent_settled`：底层 run 结束后可能继续重试、压缩或跟进；管理器不能仅凭 `agent_end` 判定可安全更新。最终激活还需要互斥屏障，不能用一次空闲观察代替。
- 关闭 stdin 是文档给出的有序退出请求；仍需处理启动失败、异常退出和关闭期限。控制器只能管理自己创建并核实身份的进程，不能从可复用 PID 猜测归属。

这些信息只为下一阶段的原生启动/等待空闲/停止接口服务。拆包阶段的零 Pi Hub 启动测试，不是已经完成原生 Pi 创建、恢复或升级的证据。正式实现须针对锁定的 Pi 版本重核 CLI 和协议，并使用隔离 agent 目录与合成 provider 验收，不加载真实用户凭据。

安全边界补充：临时 HOME 是测试数据隔离，不是对同 UID 原生 Agent 的 OS 权限隔离。Agent 若拥有宿主机同一用户的文件读取/进程执行权限，单靠 0600 配置或应用层 MCP scope 不能保护同一用户的管理员/执行器凭据。本轮没有实现这种原生执行隔离；后续须固定实际账户/容器边界后验证，不能从容器或伪客户端的 403 测试推断原生同用户安全。
