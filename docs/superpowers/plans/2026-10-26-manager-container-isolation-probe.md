# Manager 临时容器权限隔离验证

日期：2026-10-26。用户已同意新建临时容器和测试卷；不授权生产迁移。

本计划落实已批准拆分设计第 2、6、7 节中的权限域验证，是下一阶段 Task 3 的前置实验，**不是 Task 3 服务实现或 Docker 生命周期后端**。

## Global Constraints

- 仅创建带本次随机标识和专用标签的测试容器、卷；不使用真实 Pi、Hub、Gate、凭据、会话卷或已有工作区挂载。
- 控制器独自使用宿主 Docker；任何测试容器均不挂载 Docker socket，不使用 privileged、host PID、host network、宿主 HOME 或系统根目录。
- 固定已有本地镜像的完整 image ID；禁止隐式 pull。所有长期测试角色非 root、cap-drop ALL、no-new-privileges、只读根、无网络、资源/日志限额。
- 新卷的临时初始化助手可使用 root 和最小 CHOWN/FOWNER/DAC_OVERRIDE 能力，仅对本次显式新卷设置权限，随后退出。
- 公共入口、执行器与 Agent 使用不同 UID 和不同挂载。真实 TaskStore 仅由执行器持有单个写入者。
- Agent 能提交/查询允许的请求，不能批准、直接调用执行器、修改权威状态/策略/执行代码、读取管理员凭据；前端也不能取得审批通道或 Docker 控制权。
- 审批只通过管理员专用 Unix socket；执行提交只能传冻结的 `{taskId, revision}`，执行器独立核对批准的请求及策略摘要。测试动作只能在新控制卷写固定标记，不执行 shell、Pi 或 Docker。
- 这是实际容器边界与未来协议模式的实验。实验内协议代码不是生产执行器，不能据此宣称网页/MCP/完整 Pi 生命周期已经实现。
- 清理先核对确切资源 ID 和本次标签，只删除本次新资源。不能 prune，不能按宽泛前缀清理。失败/中断记录残留和明确清理方式。
