#### I1 — Exclude generated Python caches consistently from source identity and package contents

- **Files:** `scripts/manager-dist.mjs:88` (especially `:94`–`:96`), `scripts/manager-dist.mjs:109`, `package.json:42`; cache-producing fixture launch at `tests/socket/hub-gate-live.test.ts:22`.

The current recorded inventory contains 73 files, while the read-only current inventory contains 91: exactly 18 additional Python 3.14 bytecode files, **zero changed files and zero missing files**. The recorded `dist/hub/pi-web-hub.mjs` hash still matches. Thus the reported verifier failure is cache sensitivity, not production-source drift.
- **Packaging consequence:** The package's explicit directory inclusion does not inherit the root `.gitignore` exclusion as a reliable packaging policy. Read-only enumeration with the installed npm-packlist implementation returned **97 package files, including all 18 bytecode files**, no selected symlink files, and no missing manifest-listed files. No new tarball was created by this reviewer. A scripts-disabled pack from this tree therefore selects caches absent from the recorded manifest; a normal prepack rebuild would instead incorporate those local caches into the source/build identity. Neither deleting caches ad hoc nor regenerating the manifest to bless them fixes the contract.
- **Why it matters:** Running a legitimate Python fixture or importing the shipped Gate can invalidate the advertised distribution check without a source edit. Builds/packages also become dependent on local interpreter cache state and can ship artifacts expressly excluded by the migration constraints. Filtering the verifier alone would leave the cache leak in the archive.
- **Required fix:** Define a narrow generated-cache policy shared by source inventory and packaging (including relevant `__pycache__` directories and bytecode files), keep unexpected real sources/drift detectable, and retain fail-closed source/output symlink checks. Do not silently follow links or use a blanket ignore rule that weakens the declared boundary. Preventing fixture bytecode writes is useful hygiene but cannot replace installed-package/cache stability.
- **Focused acceptance:** Existing clean manifest remains valid after synthetic cache creation; build identity is unchanged by caches; a real extracted archive excludes caches and verifies itself; real source mutation still fails; symlinked source/output entries still fail, with explicit tests for the chosen cache-name/link policy.
