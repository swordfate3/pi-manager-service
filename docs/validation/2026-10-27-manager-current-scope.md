## 两个产品

- Pi Web `v1`：Pi 内加载的聊天扩展；独立验收记录在 Web 仓库。此次继续开发没有修改它，也没有给正在使用的扩展安装更新。
- Pi Manager：本仓库中的独立管理产品，合并原 Hub 门户与 Gate 的管理职责；不能等 Pi 启动后再由 Pi 加载管理器。

一个主管入口在可信本机开发时启动公共入口、独立管理员入口、任务执行器、会话门户四个服务。四个服务不是四套产品，也不意味着端口分离就实现了权限隔离。

`7483548` 修正准备阶段日志写入／同步结果不明时的处理：在进入取消原会话输入隔离的路径前先锁定不确定状态，不靠错误文本判断。独立复审认为 R1 已解决，未发现新增重要问题。

此前受限检查点已执行 13 项文件系统／受控边界协调器回归、22 项版本目录／执行器／等待空闲回归；它们不等于实际候选程序切换验收。新授权后的 68 项组合还补跑了真实 IPC 空闲观察器；实际候选切换另行执行并通过，不混算。

首次实际切换测试失败于最后新建空会话没有落盘；核对 Pi 的延迟持久化行为后，测试增加实际生成再检查新会话。完整重跑通过，未放宽任何后端安全校验；两处测试改动经独立定向审查 PASS。**没有对话的空会话仍不支持当前持久会话更新路径**，这不是已修复的产品功能。

## 新接入的只读版本目录

`c82602f` 增加了公共／管理员 `POST /api/manager/versions`、`ExecutorClient.versions()`、MCP `manager_list_pi_versions` 和管理页的搜索／分页。只查询固定的官方 Pi 包；不能通过请求指定 registry、包名、传输或超时。目录展示不代表某版本兼容，也不会创建、批准或执行更新任务。

目录查询不占任务变更队列；同一目录刷新合并，请求数量有上限。Manager 的官方元数据请求最多等 2500 毫秒，保留现有 RPC／HTTP 的超时限制。页面区分最新目录、过期缓存和不可用；后发搜索或退出登录后，不接受旧查询回填页面。

定向审查发现管理员退出请求尚未返回时，旧目录查询仍可能回填。`154d8ea` 在退出处理的第一个 await 前使查询代次失效；受控分发脚本先观察到 RED（5 通过／1 失败），修改后 6/6 通过。

后续定向复审发现，退出失败会让已取消查询的状态停在“查询中”。`4adfd52` 增加退出期间的暂停状态和失败后的明确重试状态，不把失败说成退出成功。负面回归先观察 RED（6 通过／1 失败），修改后 7/7 通过。本轮已运行真实浏览器的目录显示、搜索和成功退出清空；失败退出竞态仍由上述受控脚本验证，不将其冒称浏览器故障注入结果。
