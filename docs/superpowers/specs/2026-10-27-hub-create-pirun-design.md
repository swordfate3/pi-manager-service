# Hub 网页创建 Pi 容器

用户已确认：在 Hub 提交、在 Hub 管理员页面批准创建，不要求终端 approve；先实现此功能，不扩展更新系统。源码先在隔离分支开发，不替换当前三个 Pi 或生产配置。

## 目标与权限

复用独立 Manager 的申请、审批、执行器和聊天四角色。申请者选择允许的已存在目录、填写实例名并提交；管理员使用独立管理员身份在网页核对精确任务后批准。管理员凭据不传给 chat、public、MCP 或 Pi；申请者无法自我批准。管理员自己提交的任务仍不允许自己批准，避免悄悄取消已有独立审批保证。

在当前本机部署，管理页面保持各自来源；不将管理员页面混入聊天域名路径或绕过 Origin。生产手机管理入口的 HTTPS 配置另行授权，不以测试本机页面代表手机已可用。

## 目录

管理员可配置宿主 Home 与其内一个或多个项目根目录，不硬编码用户名或目录名。允许浏览根目录下已存在目录、提交相对路径；不提供任意宿主路径、文件读取、mkdir 或删除。禁止根目录逃逸、绝对路径、反斜杠、NUL、点段、越界符号链接以及管理/凭据/源码目录重叠。查询目录和实际执行前都重新检查策略；审批绑定所保存的目录选择。

默认没有启用浏览策略，旧的静态 workspaces 选择继续工作；缺失后端时不能为创建按钮伪报就绪。对用户只返回允许根 ID、相对路径和目录显示名，不披露其他宿主路径或原始 FS 错误。

## 启动模板

扩展已有 Docker 后端，支持管理员固定的普通 Pi 环境模板：精确镜像 ID、指定 Pi 程序/环境卷、模型目录、明确授权的固定变量和只读挂载。新增实例拥有独立可持久化 home/会话位置；共享程序、模型和扩展只有管理员显式配置后使用。不能默认继承整个宿主 Home、SSH、API key 或现有用户全部扩展。

Pi UID/GID1000:1000、cap-drop ALL、no-new-privileges、只读根、资源与日志上限保持。Web 模式允许 host 网络但不承诺网络隔离。每实例独立登记凭据，启动后等待实际 Web 登记再宣称可聊天；容器 running 本身不算模型可用。恢复不重建或删除 home，不接管外部 pirun。

## 分角色登记与信任边界

容器化执行器不直接读取聊天服务的私有配置/授权状态。聊天服务另开独立 Unix 登记签发 socket，使用专用 bearer 摘要认证；只接受固定任务 UUID 与实例标识，不接受调用方路径或 backendHost。执行器收到的只是签发成功/本任务登记就绪，不包含注册密钥、管理员凭据或整个会话清单。签发器把任务 UUID 绑定写入受现有预算限制的私有 grant，并在同一写锁下恢复重复请求，避免 grant 已写而导出尚未完成时重复签发。

单实例凭据由聊天服务写到私有导出目录，固定宿主坐标下的单个文件以只读方式直接挂到 Pi；不把导出目录挂给执行器。普通 Pi 只获得自身凭据与登记 socket，不获得签发 socket。此部署要求 Chat/Pi 同为 UID1000；签发 IPC 可用专用组将 Chat 与 executor 相连，其他服务与 Pi 不加入该组。宿主 daemon 坐标和容器内 socket/认证文件坐标分别声明，不推断二者相同。

持有原始 Docker socket 的执行器本身是受信 daemon 管理权限主体；Unix 文件分权与登记接口不构成对“已被攻陷的执行器”的防护。若要防护该主体，另需 daemon 授权策略或独立固定动作代理，不在本次创建功能中声称已经实现。

QQ 截图衔接必须保持宿主写/容器只读以及同工作区最后消费者退出再清理；需要可靠生命周期协调，不能简单照搬交互 shell trap 或声称一个静态挂载已实现监听。其他部署没有 QQ 时正常运行。若本轮无法完成此项，验收必须明确未完成，不宣称与 pirun 完全等价。

## 交付与验证

先写失败测试，再实现。覆盖路径越界、符号链接、私有目录过滤、审批前不创建、申请者无审批权限、任务幂等、精确容器归属、stop/start 保留数据、页面状态和重启恢复。真实容器测试只使用新临时目录和卷，不挂现有生产 Pi 卷/凭据，不发送真实模型请求；模型回答使用显式测试 provider 验证并区分真实 provider 未验收。

只有完整启动配置和真实隔离测试通过后才可申请上线。未部署前，不能称生产 Hub 已开放创建。
