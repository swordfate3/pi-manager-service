# Manager / Hub 连接恢复修复

## 后续：暂时不可用被误报为“从总管重新打开”

用户补充的症状是网页要求返回 Hub 重新打开，而非仅模型输出中断。本轮在隔离真实 Hub 中复现了两个误判：

- 普通会话路由的后端身份验证超过 1500ms，旧实现直接注销登记并返回410；即使该 Pi 的另一个浏览器连接仍在线，也会一起被断开。
- 已绑定的精确后继会话在恢复接口中暂时验证失败，旧实现同样返回410，使 Web 永久停止自动恢复。

最小修复为验证失败关闭、不转发数据，但对于仍在租期内且未撤权／替换的精确目标返回503，不注销登记。恢复能力期限、精确目标、运行时绑定、退出、撤权及租期失效规则保持不变；不扩大租约、不改为从列表任选会话。

验证记录：

- 新增真实 HTTP/WebSocket 用例先RED（2失败、1通过），修复后3/3通过；覆盖当前 bounded-v2 登记、另一个标签页不被注销、原路径自行恢复、精确后继重试及验证期间撤权。
- 完整 Hub socket 回归113/113通过；登录代理／心跳／转发队列定向回归16/16通过；Web 客户端与生命周期回归30/30通过。
- 外层 Manager 登录 → Hub → 真实隔离 Pi → Chromium 手机视口：注入一次后继恢复503和两次原路径HEAD503，自动恢复同一目标且保留草稿、不重放提问，1/1通过。首次运行停在临时账号登录的导航等待；补充初始化响应成功断言后重跑通过，不归为恢复代码断言失败。
- 已查看390×844截图，恢复后连接状态、原会话及草稿可见，无横向溢出。浏览器替代验证不等于手机实机验证。
- 构建与分发一致性检查通过。修复与测试在独立开发工作区完成；本轮未推送、未部署、未重启 Hub／隧道／Pi，不修改生产数据或凭据。
- 独立只读审查未发现阻断项；重点检查了异步验证后的撤权、租期／运行时绑定、多标签页及精确后继边界。测试数字由主代理运行核对，审查者未重复执行测试。

这些证据确认一条会造成相同提示的代码缺陷，不证明已捕获用户每次真实中断的最初触发源；前端4秒健康探测的误断风险也不能在本次 Hub 状态码修复中冒称已消除。

## 已定位的问题

- 外层Manager仅允许会话页面和列表，不允许浏览器的 `POST /api/session-handoff`，并过滤了该接口必需的能力头，导致内部Hub正常而外层返回404。
- Hub终止并重新建立两个WebSocket连接。Pi发出的ping由Hub应答，不能自动维持浏览器到Hub这一段。

## 修复范围

- 在现有登录与精确Origin校验之后转发handoff；仅该精确POST接口携带恢复能力，不传入Pi的普通HTTP或WebSocket。鉴权cookie和Authorization仍不转发。
- 浏览器侧每20秒发ping，连续三个探测未获pong并经过应答窗口后退役连接；close/error清理计时器与监听器。按实际探测次数计数，不把事件循环停顿的墙钟时间算成多次失败。
- 干净安装重建发现Vite默认将MCP包外置，导致既有“归档只带ws运行依赖”测试失败；构建显式打包非Node依赖并保留ws外置，避免发布包依赖开发环境。
- Web独立v1分支增加前台20秒只读探测；健康周期不同步历史，恢复事件仍合并同步，不重放写操作。本项目不引入旧部署兼容。

## 验证

- 恢复接口和真实浏览器心跳先RED后GREEN；鉴权、跨站、无效能力、精确successor、能力不泄露、注销撤销保持有效。
- Manager单元683项：675通过、8个既有可选skip；定向心跳和外层传输12/12通过。
- 全部Hub socket测试串行110/110通过。最初并发运行有一次Gate fixture启动超时，单独和完整串行复跑均通过，未修改超时策略。
- 配套Web单元487通过/1可选skip；真实隔离Pi、外层Manager登录、Hub、Chromium的 `/new`、`/resume`、连续可见页面断网恢复1/1通过，未重复提问且保留草稿。390×844、1440×900截图已人工查看。
- 使用临时目录、测试账号和合成模型，不使用生产会话或凭据。不能据此声称所有真实手机网络断连已消除，也不把心跳缺口断言为每次历史掉线的原因。
- 旧 `deploy/stack` 安装测试依赖仓库未跟踪的 `prepare-start.mjs`，干净分支中仍失败；本次不补旧兼容路径。当前生产使用 `deploy/compose`，其配置与启动器回归不依赖旧文件。
