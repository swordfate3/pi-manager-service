## 审批与执行器的实际权限边界

批准设计要求公共 HTTP/MCP 入口不能直接持有原生进程或 Docker 控制权，Agent 不能自行批准管理动作。单独的 JavaScript 进程、临时 HOME 或 0600 文件，均不能保护同一宿主 UID 下的管理员文件免于不受限 Agent 的访问。

因此先实现私有任务存储与受管原生后端，**不接入公共管理接口**。不能把本地库调用测试当作“已实现安全的网页/MCP 审批”。要继续开放不可信 Agent 的管理能力，必须先落实并验证不同 OS 账户/容器的权限域；这一部署选择不由代码库单方面修改宿主环境来代替。

本轮未实施新的 HTTP 主管入口、管理网页创建闭环或 MCP 服务。不提供指向未实现接口的启动命令。

实际权限域核对保存在 `docs/research/2026-10-26-manager-executor-authority.md`。账户或容器分离尚未选择和验收；当前没有新增账户、容器、提权规则或生产部署。Task 3 开放执行前必须解决这一点，不以同 UID 的开发模式冒充隔离完成。
